- 検索だけを実行して見つかったページと、その本文で確認できたこと：
  - `uv run python -m app.retrieval "LoRA QLoRA 違い"` では、検索結果 1 が `lec02-main-p052`、検索結果 2 が `lec02-main-p051` で、どちらも正答の根拠になっていた。
  - 返ってきた本文で確認できたのは、`p.052` の「元の重みは固定し、小さな『差分』だけを学習する（LoRA）」「さらに元の重みを 4bit に圧縮する（QLoRA）」という説明だった。
  - `p.060` や `p.061` のような似た用語のページは、回答の説明に直接必要な内容ではなく、正答の根拠は `p.51` と `p.52` に集中していた。単なる用語の出現と、答えの根拠は区別できた。
- `--trace`で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：

  - ベクトル検索: `search_materials({'query': 'LoRA QLoRA 固定 学習 第2回'})` が呼ばれ、`search_materials` を 1 回実行して p.52 を拾っていた。

- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：
  - この質問では、`p.51` と `p.52` の取得自体は十分で、特に `p.52` の本文が決定打だった。
  - 全文投入だけは、内容はあるが「直接的に答えてはいない」形になっており、必要な根拠を使えない現象が見られた。入力制限の失敗ではなく、根拠を正しく処理しきれなかったケースである。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  - この質問では、ベクトル検索が最も安定しており、必要なページを最小限で引けるので採用しやすい。
  - Tree は根拠の探索経路が追いやすく、説明に適しているが比較的多くのツール呼び出しが必要だった。
  - Graph は入口を見つけるのが速く、近傍情報も使えるが、「近い用語」だけが多いと答えの根拠に使いづらいことがある。
  - 全文投入は短い質問であれば便利だが、長い資料や多くの根拠を含む場合は入力量と回答の曖昧さが残る。

- やったこと（変更したファイル・設定・処理、または設計した取得方法）：

  - 同じページが重複しないように `seen` で除外し、各候補に `neighbor_context` を付けるように整理した。
- 比較した質問と、固定した条件（モデル・対象資料など）：
  - 質問: 「第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？」
  - モデル: `gemini-3.5-flash-lite`
  - 対象資料: `lec01-main` / `lec02-main` / `lec03-main` の既定検索DBと講義本文
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：
  - 変更前の `search()` は `lec02-main-p052` → `lec02-main-p051` → `lec02-main-p060` の順で回収され、根拠の前後の説明文脈が不足していた。
  - 改善後の `search_with_neighbors()` は `p052` に `['lec02-main-p051', 'lec02-main-p053']` を含め、`p051` に `['lec02-main-p050', 'lec02-main-p052']` を含めるようにした。これにより、「元の重みを固定し、小さな差分を学習する」という説明の前後文脈を、同じ資料上で取れるようになった。
  - 実際のエージェント実行では、`search_materials({'query': 'LoRA QLoRA 固定 学習'})` を呼び、回答は p.51 と p.52 を繋いで「LoRA は元の重みを固定し、A/B だけを学習」「QLoRA は LoRA に 4bit 圧縮を加える」と説明した。
  - `--trace` の実測値: `時間 3.23 秒`, `入力 4,911 tokens / 出力 221 tokens / モデル応答 2 回`, `生成API推定コスト $0.002026 USD`。
  - 変更前の比較値（同じ質問で実行済み）: `時間 3.26 秒`, `入力 3,037 tokens / 出力 171 tokens / モデル応答 2 回`, `生成API推定コスト $0.001339 USD`。前後の根拠を付けたことで、入力は増えたが、説明の裏付けが強くなった。
- 改善した例と、残る失敗・制約：
  - 改善した例: p.52 の説明が p.51 の「PEFT の概要」や p.53 の「FT と QLoRA の使い分け」に繋がっているので、LoRA/QLoRA の違いの説明がより自然になった。
  - 残る制約: `context_window=1` では 1 ページ前後しか見ないため、章をまたぐ説明や、複数ページにまたがる詳しい説明ではまだ不足する。根拠が候補の前後に出ていないときは、検索語の設計や別の探索経路が必要になる。
- 気づき・疑問：
  - 「検索結果に前後ページを足す」だけで、根拠のつながりがかなり説明しやすくなる。
  - 一方で、文脈を増やすと検索のノイズも増えるので、採用する際は `context_window` と `RAG_TOP_K` のバランスを意識する必要がある。
  - 質問の意図が「概念の違い」なら、連続ページの補強が効くが、「比較の納得感」までは答えを支える引用の質が重要になる。
